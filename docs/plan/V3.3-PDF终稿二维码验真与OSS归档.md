## 1. 背景与目标

### 1.1 业务诉求

| 诉求 | 说明 |
|------|------|
| 交付格式 | 用户打印、对外交付需要 **PDF**，一页对应编辑器的一逻辑页 |
| 云端归档 | 终稿必须 **上传 OSS**，作为「合同原件」唯一来源 |
| 防伪造 | 确认锁定后，PDF **每一页** 印有二维码 |
| 扫码验真 | 扫描二维码可验证是否为系统出具的正式合同 |
| 查看原件 | 验真通过后，可在线查看/下载 OSS 上的同一份 PDF |
| 协作期导出 | 未确认前可导出「草稿 PDF」（无正式验真码或验真显示未确认），便于预览 |

### 1.2 与现有能力的关系

| 现有能力 | V3.3 处理方式 |
|----------|----------------|
| `preparePagesForExport()` + `html-to-image` 逐页截图 | **保留**，作为 PDF 页图来源 |
| `POST /export-png` 多文件 OSS 归档 | **由 PDF 归档替代**（见 §8 迁移策略） |
| `POST /confirm` 仅写确认记录、改状态 | **扩展**：确认成功后必须完成终稿 PDF 生成并归档 |
| V3「浏览器导出、禁止服务端截图」 | **不变**；PDF 拼装、二维码叠加仍在浏览器完成 |
| 纸内「第 n 页」页脚 | **保留**，二维码为额外叠加层，不进入可编辑 DOM |

### 1.3 一句话定义

> **网页编辑定稿 → 确认锁定 → 浏览器按页截图 → 每页叠加验真二维码 → 合成 PDF → 上传 OSS → 扫码打开公开验真页查看原件。**

## 2. 用户流程

### 2.1 内部用户（合同详情页）

```text
编辑并保存版本
    →（可选）导出草稿 PDF：带「草稿」水印，无正式验真码
    → 点击「确认合同」
    → 前端自动生成终稿 PDF（每页二维码 + 无草稿水印）
    → 上传 OSS，后端写入 verify_code / pdf_hash
    → 确认成功；合同状态 = 已确认（锁定）
    → 本地下载同一份 PDF；后续可从详情页「下载终稿」
```

**约束**：确认操作与终稿归档 **原子绑定**——OSS 上传或验真码写入失败时，确认应失败并提示重试，避免出现「已确认但无原件」。

### 2.2 外部协作者（分享页）

与内部流程一致：可编辑保存 → 确认 → 生成终稿 PDF → OSS 归档。验真码与合同版本绑定，不区分内外部确认人。

### 2.3 扫码验真（公开，无需登录）

```text
手机扫描 PDF 任意页二维码
    → 打开 https://{域名}/verify/{verify_code}?page={n}
    → 展示：合同编号、名称、版本号、确认状态、确认人、确认时间、页数
    → 验真结果：有效 / 无效（未确认、版本不存在、码被篡改等）
    → 「查看合同原件」：OSS 签名 URL 打开 PDF（新标签或内嵌预览）
```

## 3. 技术架构

### 3.1 终稿生成管线（浏览器）

```text
DocumentEditor.preparePagesForExport()
        ↓
exportPagesAsPng()          // 已有：逐 .doc-page 截图
        ↓
[每页] overlayQrWatermark() // 新增：canvas 右下角叠二维码
        ↓
exportPagesAsPdf()          // 新增：jspdf，一页一图，A4 尺寸
        ↓
uploadContractExportPdf()   // 新增：multipart 单 PDF + hash
        ↓
后端：OSS + DB 更新 verify_code / export_pdf_*
```

### 3.2 二维码内容

**URL 格式**（正式终稿）：

```text
https://{PUBLIC_WEB_ORIGIN}/verify/{verify_code}?page={pageNo}
```

| 字段 | 说明 |
|------|------|
| `verify_code` | 后端生成并落库的不可猜短码（建议 16～24 位 Base62），与 `contract_id + version_id` 唯一绑定 |
| `page` | 1-based 页码，便于验真页定位「您正在查看第 n 页」 |

**草稿 PDF**（未确认前手动导出）：

- 方案 A（推荐）：二维码 URL 带 `draft=1` 或 verify_code 为空，验真页显示「草稿，未经确认」
- 方案 B：草稿 PDF **不打二维码**，仅「草稿」文字水印（实现更简单）

本计划采用 **方案 B**：草稿仅文字水印；**正式二维码仅在确认归档流程中生成**（verify_code 由后端在确认前预分配或确认时一并返回）。

### 3.3 验真码生成时机

推荐流程：

```text
1. 用户点击「确认合同」
2. POST /api/contracts/{id}/prepare-final-export  → 返回 { verify_code, upload_token? }
3. 前端生成 PDF 并 POST /api/contracts/{id}/export-pdf（含 verify_code、hash、pdf 文件）
4. 后端校验版本未锁定 → 写 OSS → 写 DB → 写确认记录 → 状态改为已确认
```

或将步骤 2～4 合并为 **单次 `POST /confirm` 携带 multipart PDF**（减少往返，但请求体较大）。  
**待做清单中两种都列出，实施时二选一并在代码注释中固定方案**（推荐：确认接口改为 `multipart`，一次提交 PDF）。

### 3.4 二维码版式

| 项 | 规格 |
|----|------|
| 位置 | 每页右下角，距纸边约 8mm（换算为截图像素按 A4 比例） |
| 尺寸 | 约 18～22mm 正方形 |
| 旁注 | 可选一行小字：「扫码验真」 |
| 层级 | 叠在截图之上，**不修改** `document_content` |
| 不进编辑区 | 与翻页条一样，仅存在于导出合成阶段 |

依赖：`qrcode`（生成 Data URL）+ Canvas 合成，或 `jspdf` 的 `addImage` 直接贴二维码图。

### 3.5 PDF 页面尺寸

与 V3.1 纸张一致：**A4 纵向**

| 属性 | 值 |
|------|-----|
| 物理尺寸 | 210 × 297 mm |
| 截图 | `pixelRatio: 2`，宽度与 `computePaperLayout().pageWidthPx` 一致 |
| PDF | `jsPDF({ unit: 'mm', format: 'a4', orientation: 'portrait' })`，每页 `addImage` 满版铺图 |

## 4. 数据模型

### 4.1 迁移脚本 `sql/migrate_v4.sql`

```sql
-- V3.3：PDF 终稿归档与扫码验真
ALTER TABLE contract_version
  ADD COLUMN export_pdf_oss_key    VARCHAR(500) DEFAULT NULL COMMENT '终稿 PDF 在 OSS 上的 object key',
  ADD COLUMN export_pdf_hash       VARCHAR(64)  DEFAULT NULL COMMENT 'PDF 文件 SHA256',
  ADD COLUMN export_pdf_page_count INT NOT NULL DEFAULT 0 COMMENT 'PDF 页数',
  ADD COLUMN pdf_exported_at       DATETIME     DEFAULT NULL COMMENT 'PDF 归档时间',
  ADD COLUMN verify_code           VARCHAR(32)  DEFAULT NULL COMMENT '扫码验真短码（唯一）',
  ADD UNIQUE KEY uk_verify_code (verify_code);
```

说明：

- `export_png_*` 字段 **保留**（历史数据兼容），新终稿以 PDF 为准。
- `verify_code` 在终稿归档成功时写入；未归档版本为 NULL。

### 4.2 验真查询所需字段（无需新表）

公开验真 API 通过 `verify_code` 关联：

- `contract`：`contract_no`、`contract_name`、`status`
- `contract_version`：`version_no`、`export_pdf_*`、`verify_code`、`pdf_exported_at`
- `contract_confirmation`：最近确认记录（确认人、时间）

可选：若需审计扫码行为，二期再加 `contract_verify_log`；**本计划不强制**。

## 5. API 设计

### 5.1 新增 / 调整

| 方法 | 路径 | 说明 |
|------|------|------|
| `POST` | `/api/contracts/{id}/export-pdf` | 上传终稿 PDF（multipart：`file` + `hash` + `page_count` + `verify_code`）；写 OSS + 更新 version |
| `GET` | `/api/contracts/{id}/export-pdf` | 当前版本已归档 PDF 信息 + OSS 签名下载 URL |
| `GET` | `/api/contracts/{id}/versions/{vid}/export-pdf` | 历史版本 PDF 信息（只读） |
| `POST` | `/api/share/{token}/export-pdf` | 外部分享页上传 PDF（权限校验同分享编辑） |
| `GET` | `/api/public/verify/{verify_code}` | **公开**，query：`page`（可选）；返回验真信息与 PDF 签名 URL |
| `POST` | `/api/contracts/{id}/confirm` | **改造**：`multipart/form-data`，必填 PDF 文件 + hash + page_count；成功则确认 + 归档原子提交 |
| `POST` | `/api/share/{token}/confirm` | **同上**（外部分享确认） |

### 5.2 `POST /export-pdf` 请求

```http
Content-Type: multipart/form-data

file:         (binary) application/pdf
hash:         (string) SHA256 hex
page_count:   (int)
verify_code:  (string) 与 DB 预生成或确认流程下发的一致
draft:        (optional) "1" 表示草稿归档（不写 verify_code、不触发确认）
```

### 5.3 `GET /api/public/verify/{verify_code}` 响应

```json
{
  "valid": true,
  "reason": "",
  "contract_no": "HT-2026-001",
  "contract_name": "某某采购合同",
  "version_no": 3,
  "status": 3,
  "status_text": "已确认",
  "confirmed_at": "2026-09-01T12:00:00+08:00",
  "confirmers": ["张三", "李四（外部）"],
  "page_count": 12,
  "scanned_page": 3,
  "pdf_url": "https://oss.../signed-url",
  "pdf_hash": "abc...",
  "exported_at": "2026-09-01T12:00:00+08:00"
}
```

`valid: false` 时 `reason` 说明：未找到、未确认、无归档 PDF、hash 不匹配等。

### 5.4 废弃（实施后标记 deprecated）

| 方法 | 路径 | 说明 |
|------|------|------|
| `POST` | `/api/contracts/{id}/export-png` | 前端不再调用；保留 1 个版本周期后删除 |
| `GET` | `/api/contracts/{id}/export-png` | 同上 |

### 6.3 安全

| 项 | 措施 |
|----|------|
| `verify_code` | 密码学安全随机，全局唯一索引 |
| 公开验真 | 仅返回必要元数据 + **短时** OSS 签名 URL（如 15 分钟） |
| 上传 PDF | 校验 `hash` 与文件内容一致；限制大小（如 50MB） |
| 确认原子性 | DB 事务：确认记录 + version PDF 字段 + contract.status 同事务提交 |
| 防重放 | 同一版本重复确认返回幂等或明确错误 |

### 6.4 环境变量

| 变量 | 说明 |
|------|------|
| `PUBLIC_WEB_ORIGIN` | 生成二维码 URL 的前端域名，如 `https://contract.example.com` |

### 7.4 确认流程（前端伪代码）

```ts
async function handleConfirm() {
  await blurEditor()
  const pages = await editorRef.preparePagesForExport()
  const verifyCode = await fetchVerifyCodeForConfirm(contractId) // 或由 confirm 响应返回
  const pageImages = await exportPagesAsPng(pages, { draft: false })
  const withQr = await Promise.all(
    pageImages.map((blob, i) => overlayQrWatermark(blob, verifyCode, i + 1))
  )
  const pdfBlob = await exportPagesAsPdf(withQr)
  const hash = await sha256(pdfBlob)
  await confirmContractWithPdf(contractId, { file: pdfBlob, hash, page_count, verify_code: verifyCode })
}
```

若采用「confirm 单次 multipart」方案，则去掉单独的 `prepare-final-export` 调用。

## 9. 验收标准

| ID | 场景 | 期望 |
|----|------|------|
| A1 | 协作中点击「导出 PDF」 | 下载草稿 PDF，无正式验真码，可有「草稿」水印 |
| A2 | 点击「确认合同」 | 自动生成带每页二维码的 PDF，上传 OSS，确认成功，合同锁定 |
| A3 | 确认失败（网络/OSS） | 合同 **不** 变为已确认，提示重试 |
| A4 | 扫码任意页二维码 | 打开验真页，显示有效、合同信息、当前页码 |
| A5 | 验真页「查看原件」 | 打开与 OSS 一致的 PDF |
| A6 | 篡改 verify_code | 验真 `valid: false` |
| A7 | 未确认版本扫码 | 无 verify_code 或 `valid: false` |
| A8 | 分享页确认 | 与详情页行为一致 |
| A9 | PDF 页数 | 等于编辑器逻辑页数，顺序一致，含纸内「第 n 页」 |
| A10 | 历史版本 | 可查看该版本是否已有 PDF 归档及下载 |

## 12. 风险与对策

| 风险 | 对策 |
|------|------|
| 确认请求体过大 | 限制页数上限提示；PDF 压缩；超时调大网关 |
| 浏览器生成 PDF 慢 | 确认按钮 loading；页数多时在 UI 提示预计时间 |
| OSS 上传失败导致确认卡住 | 事务回滚 + 明确错误；支持重试确认 |
| 二维码过小难扫 | 最小边长 18mm；扫码测试多种打印机 |
| `PUBLIC_WEB_ORIGIN` 配错 | 启动时校验；管理后台可配置 |
| 旧 PNG 数据 | 验真页兼容提示，不强制迁移 |

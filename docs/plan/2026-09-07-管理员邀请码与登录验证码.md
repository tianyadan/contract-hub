# 管理员用户管理、邀请码注册与登录图形验证码

## 1. 背景

系统当前开放注册、无管理员用户治理能力，登录缺少防暴力破解手段，不利于内测与正式使用管控。

## 2. 开发目标

1. 管理员可对用户：封禁、启用、软删除、重置密码为默认 `12345678`
2. 注册必须填写管理员生成的邀请码（一次性、5 分钟有效）
3. 登录连续失败 3 次后展示图形验证码

## 3. 实现范围

### 本次实现

- DB：`sys_user.role`；`status=2` 软删语义；`invite_code` 表；管理员种子账号
- 后端：注册邀请码校验、登录失败计数 + 图形验证码、管理员用户/邀请码 API、JWT role、RequireAdmin
- 前端：注册邀请码、登录验证码、管理员用户管理页、邀请码管理页

### 本次暂不实现

- 短信/邮箱验证码、Redis 共享会话、硬删除与级联清理、自定义重置密码、复杂 RBAC

## 4. 技术设计

### 数据

- `sys_user.role`：0 普通 / 1 管理员
- `sys_user.status`：0 封禁 / 1 正常 / 2 软删除
- `invite_code`：code 唯一；expire_at；used_at / used_by_user_id
- 种子用户：`admin` / `12345678` / role=1（无管理员时插入）

### 接口

- `POST /api/auth/register` + `invite_code`
- `GET /api/auth/captcha`；`POST /api/auth/login` + 可选 captcha
- `/api/admin/users*`：列表 / ban / enable / reset-password / delete
- `/api/admin/invite-codes`：生成（及列表）

### 规则

- 邀请码：未使用且未过期才可注册；注册事务内核销
- 验证码：失败次数按 username+IP；≥3 强制；成功清零
- 管理员：不可删/封自己；不可处理最后一个管理员
- 重置密码：固定 `12345678`，无需管理员输入

### 前端

- Ant Design 管理页；侧栏仅 `role===1` 可见「系统管理」
- 登录失败满 3 次展示验证码图片（可刷新）

## 5. 变更影响

- 注册接口破坏性变更：无邀请码失败
- `UserVO` / JWT 增加 `role`
- 登录失败路径可能返回「需要验证码」业务码
- 新增 SQL 迁移 `migrate_v9.sql`；Docker MySQL bootstrap 需纳入（本地/服务器下次部署）

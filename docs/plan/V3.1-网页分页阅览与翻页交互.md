# V3.1 网页分页阅览与翻页交互 — 需求设计

> 基于 V3「网页即真相」：用 **Web 固定纸张分页** 替代「一整张长页」，全链路统一阅览 / 编辑 / 导出。

编写日期：2026-08-29  
状态：**已实施（2026-08-29）**  
前置文档：[V3-网页即真相与PNG导出架构.md](./V3-网页即真相与PNG导出架构.md)

---

## 1. 背景与问题

### 1.1 现状痛点

当前 `DocumentEditor` 以 **连续长纸（`doc-page--continuous`）** 渲染：导入或编辑后，全文落在**一张无限增高的白纸**上。

| 问题 | 影响 |
|------|------|
| 无法按「页」浏览 | 长合同上下滚动成本高，难定位「第几页」 |
| 与交付物心智不符 | 终稿是多张 PNG，但编辑时却是一长页 |
| 导出页切分不稳定 | 连续模式下往往只有 1 个 `.doc-page`，易导出成单张超长图 |
| 模板池与合同详情一致差 | 导入后观感像「网页文章」，不像合同纸面 |

### 1.2 业务诉求（本次确认）

1. **导入后必须分页**：不能再呈现「一整张超长页」。
2. **分页策略**：若无法可靠使用 WPS/DOCX 原分页，则采用 **Web 分页**（按纸张高度切分内容）。
3. **翻页交互**：每页底部提供 **左右箭头**，支持上一页 / 下一页。
4. **覆盖范围**（已定稿）：
   - 合同详情编辑 / 只读阅览
   - 外部分享页编辑 / 阅览
   - **导出 PNG**：按页导出多张（与屏幕所见页一一对应）
   - **模板池不做分页改造、不做导出 PNG**（模板详情保持现状即可）

### 1.3 与 V3 的关系

| V3 已定原则 | 本次如何落实 |
|-------------|--------------|
| 网页即真相 | 页边界以 **Web 排版结果** 为准，不以 WPS 页码为准 |
| 浏览器导出 PNG | 导出遍历可见/逻辑上的 `.doc-page`，一页一图 |
| 导入样式可接受偏差 | 不追求还原 WPS 分页符位置；允许 Web 重排分页 |
| 2C2G / 免费栈 | 分页与翻页全在前端完成，不引入服务端排版引擎 |

**结论**：本需求是 V3 的补强，不推翻「网页即真相」；把「纸面」从「一长页」升级为「多页 + 翻页」。

## 2. 目标与非目标

### 2.1 目标（Must）

| ID | 目标 |
|----|------|
| G1 | 任意进入编辑器的文档，默认按 **固定纸张尺寸**（默认 A4）分页展示 |
| G2 | 用户可通过页底 **左 / 右箭头** 翻页；展示当前页码（如 `2 / 12`） |
| G3 | 合同详情、分享页 **同一套分页 + 翻页行为** |
| G4 | 导出 PNG **页数 = 编辑器逻辑页数**，顺序一致，禁止再导出「单张超长图」 |
| G5 | 编辑时插入/删除内容后，分页结果 **自动重算**（可有轻微防抖） |
| G6 | 只读 / 已锁定合同同样分页 + 翻页，仅禁止内容编辑 |
| G7 | 纸内页脚 **必须显示「第 n 页」**（进入 PNG） |
| G8 | 编辑策略固定为 **按页挂载 DOM（策略 A）** |

### 2.2 非目标（Out of Scope）

| 项 | 说明 |
|----|------|
| 像素级还原 WPS 分页 | 不保证第 N 页与 Word/WPS 第 N 页文字完全一致 |
| 服务端分页 / Puppeteer | 继续禁止服务端截图与排版 |
| DOCX 分页符 100% 解析 | 有则尊重为「强制换页」；无则纯 Web 流式分页 |
| 展开全部 / 多页堆叠浏览 | **只保留翻页**，不做纵向展开开关 |
| 表格跨页 / 拆表 | **业务不会出现表格，忽略**；分页算法可不特殊处理 table |
| 模板池分页与导出 | **模板详情不改造、不导出 PNG** |
| 打印 CSS `@page` 作为主方案 | 可作为辅助，不作为主交互 |

## 3. 方案选型

### 3.1 为何不用「WPS/DOCX 原分页」作主方案

```text
DOCX 内：sectPr / w:br type=page / 行高字号 ↔ 前端 HTML 模型
```

| 难点 | 说明 |
|------|------|
| 解析丢失 | 当前 Python `/parse` 仅结构化 blocks，页边界信息不完整 |
| 样式偏差 | 字号、行距、中文字体一变，原页码即失效 |
| 编辑破坏 | 用户一改字，原 WPS 页切分必然过时 |
| 与 V3 冲突 | V3 已放弃「与原文件像素一致」，再绑死原分页会反复返工 |

**决策**：

> **主方案 = Web 固定纸张自动分页**；DOCX 显式分页符（若解析得到）仅作为 `page_break_before` **强制断页** 的可选增强。

### 3.2 推荐方案：Web 流式分页 + 单页翻页 UI

```text
┌─────────────────────────────────────────┐
│  工具栏 / 状态提示                        │
├─────────────────────────────────────────┤
│                                         │
│           ┌───────────────┐             │
│           │  第 N 页纸面   │             │
│           │  （A4 可视区） │             │
│           │  可编辑正文    │             │
│           └───────────────┘             │
│                                         │
│        ← 上一页    3 / 10    下一页 →   │
└─────────────────────────────────────────┘
```

**核心机制**：

1. **纸张模型**：宽高、页边距来自 `DocumentContent.page`（缺省 A4 + 常见边距）。
2. **内容模型**：仍为有序 `blocks[]`（或统一 contentEditable DOM），**不按页存库**。
3. **分页算法（前端）**：按块（或段落节点）累计高度，超过「正文可用高度」则切到下一页；遇 `page_break_before` 强制切页。
4. **展示**：默认只渲染 **当前页**（或渲染全部但只显示当前页），底部翻页条切换 `currentPageIndex`。
5. **导出**：对每一逻辑页生成对应 DOM（可临时离屏渲染全页），逐页 `html-to-image` → 多张 PNG / ZIP。

### 3.3 备选（不推荐作默认）

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| 多页纵向堆叠 + 滚动 | 实现简单、一目了然 | 长合同仍难浏览；与「翻页」诉求不符 | 可作「展开全部」开关 |
| 仅 CSS `overflow` 假分页 | 无算法 | 无法稳定导出多页、编辑光标跨页难 | 否决 |
| 依赖 mammoth/docx 页信息 | 导入瞬间像 Word | 编辑后立刻失真 | 仅作导入初值参考 |

## 4. 功能需求明细

### 4.1 分页规则

| 规则 | 描述 |
|------|------|
| R1 纸张 | 默认 A4 竖版；尊重 `page` 中的宽高、边距、方向 |
| R2 可用高度 | `可用高度 = 纸张高度 − 上边距 − 下边距 − 页眉区 − 页脚区` |
| R3 流式切分 | 按块顺序累加；块放不下则整块落入下一页 |
| R4 强制断页 | `page_break_before === true` 的块从新页开始 |
| R5 空页 | 不允许连续空页（末尾强制断页除外可裁剪） |
| R6 超高块 | 单块高度 > 可用高度时：整块独占一页；**不处理表格拆分**（无表格场景） |
| R7 重算时机 | 内容变更、样式变更、纸张设置变更后防抖重算（建议 100–300ms） |
| R8 纸内页码 | **必须**在页脚打印「第 n 页」（可带「共 m 页」）；**进入 PNG** |
| R9 纸外页码 | 翻页条显示 `当前 / 总页数`，仅交互用，**不进 PNG** |

### 4.2 翻页交互

| 项 | 要求 |
|----|------|
| 位置 | **当前页纸面正下方**（居中），不遮挡正文 |
| 控件 | 左箭头（上一页）、右箭头（下一页）、中间页码文案 `当前 / 总页数` |
| 禁用态 | 首页禁用左箭头；末页禁用右箭头 |
| 快捷键（建议） | `←` / `→` 或 `PageUp` / `PageDown`（焦点不在输入框编辑时）；一期可只做按钮 |
| 动画 | 可选轻微左右滑入；一期可硬切，避免影响编辑光标 |
| 导出水印 | 翻页控件 **不得出现在 PNG 截图内**（控件放在 `.doc-page` 外） |

### 4.3 编辑行为

| 场景 | 期望 |
|------|------|
| 当前页末尾继续输入 | 溢出后自动进入下一页；光标跟随到新页 |
| 当前页删除导致变短 | 后续页内容上移；总页数减少；若当前页被删空则停留在合法页 |
| 跨页选区 | 一期可不支持跨页多选；优先保证单页内编辑稳定 |
| 格式工具栏 | 仍基于当前选区；与分页解耦 |
| 只读模式 | 可翻页，不可改字 |

### 4.4 导入

| 场景 | 期望 |
|------|------|
| 合同导入 / 从模板生成合同 | 进入合同编辑器后即 **已分页**（模板池编辑页本身不改造） |
| 解析到的 `page_index` | 可作为「初始提示」或忽略；**不以之为最终页界** |
| 显式分页符 | 映射为 `page_break_before` |

### 4.5 导出

| 项 | 要求 |
|----|------|
| 页对应 | 第 i 张 PNG = 编辑器第 i 页视觉内容 |
| 禁止 | 连续长页截成一张图 |
| ZIP 命名 | `{合同编号}-001.png` … |
| 草稿水印 | 未确认合同时可加水印；翻页条不进图 |
| 归档 | 继续走现有 `export-png` OSS 接口，`page_count` = 逻辑页数 |

### 4.6 覆盖页面清单

| 页面 | 编辑 | 翻页 | 导出 |
|------|------|------|------|
| 模板详情（模板池） | ❌ 不改造 | ❌ | ❌ |
| 合同详情 | ✅ / 锁定只读 | ✅ | ✅ 多页 PNG（含纸内「第 n 页」） |
| 外部分享页 | 视权限 | ✅ | ✅（与详情一致） |
| 历史版本查看 | 只读 | ✅ | 可选导出当前查看版本 |

## 5. 数据与存储

### 5.1 原则

**分页结果默认不持久化到数据库。**

- 存库：`blocks[]` + `page` + 样式 + 可选 `page_break_before`
- 运行时：前端根据纸张与内容 **计算 `pages: BlockId[][]` 或 DOM 切片**
- 好处：编辑任意改动无需维护「页表」一致性；换纸张尺寸可立即重排

### 5.2 说明

- 不做 `view_mode` / 堆叠模式字段（产品确认 **只保留翻页**）。
- 导出页数继续复用现有 `export_png_page_count` 等字段。

### 5.3 类型侧已有能力（复用）

现有 `DocumentBlock.page_break_before`、`PageSetup`、`schema_version` / `render_mode: web_canvas` **足够支撑一期**，无需为分页新建表。

## 6. 交互与视觉规范（摘要）

1. **默认且唯一视口：单页翻页**（无「展开全部」）。
2. **翻页条**在纸外：`[‹]  3 / 12  [›]`，移动端触控区域 ≥ 44px。
3. **纸内页脚必须显示「第 n 页」**（建议文案：`第 n 页` 或 `第 n 页 / 共 m 页`），导出 PNG 可见。
4. **纸外翻页条页码**仅交互，截图时排除。
5. **加载 / 重算中**：可短暂显示「正在分页…」，避免闪烁乱页。
6. **文案提示**（导入后）：「文档已按网页纸张分页，页边界可能与 WPS 不一致，请以本页预览为准。」

## 7. 技术实现要点（设计级，非编码）

### 7.1 模块划分（建议）

```text
frontend/src/
  utils/paginateDocument.ts     # 纯函数：blocks + pageSetup → pages[]
  components/contract/
    DocumentEditor.tsx          # 接入分页状态与当前页渲染
    PageNavigator.tsx           # 左右箭头 + 页码
    doc-editor.css              # 固定页高、隐藏溢出、翻页条样式
  utils/exportContractPng.ts    # 按逻辑页离屏渲染后截图（已有，需对齐）
```

### 7.2 与 contentEditable 的关系（已定稿：策略 A）

**采用策略 A：按页挂载 DOM** — 仅挂载当前页 blocks 到可编辑区。

| 必须专项处理 | 说明 |
|--------------|------|
| 页末继续输入溢出 | 重算后自动翻到下一页，光标落到新页对应位置 |
| 页首删除 / 合并 | 内容上移后钳位当前页索引 |
| 回车产生新块 | 新块归属当前页；溢出再切页 |
| 跨页选区 | 一期不做；保证单页内编辑稳定 |

策略 B/C 明确不采用。表格场景忽略，无需拆表逻辑。

### 7.3 导出对齐

导出不得依赖「用户当前翻到哪一页」：

1. 根据同一套 `paginateDocument` 得到全部页；
2. 离屏逐页渲染固定尺寸 `.doc-page`；
3. 截图（控件、选区高亮、工具栏均排除）。

## 8. 验收标准

| # | 验收项 |
|---|--------|
| A1 | 导入任意 ≥2 页纸量合同后，编辑器总页数 ≥ 2，且非单张超长纸 |
| A2 | 页底左右箭头可翻页；首页/末页箭头正确禁用 |
| A3 | 合同详情与分享页分页/翻页行为一致；模板池无分页改造要求 |
| A4 | 导出 ZIP 内 PNG 张数 = 编辑器总页数，内容顺序正确；每张含纸内「第 n 页」 |
| A5 | 确认锁定后仍可翻页、可导出，不可编辑 |
| A6 | 未保存修改时导出仍遵循「先保存」校验（沿用 V3 P1） |
| A7 | 移动端可完成翻页与基本阅览（编辑体验可降级但不毁版） |
| A8 | 无「展开全部」入口；仅左右翻页 |

## 13. 总结

本次需求把合同从「网页长文」拉回「纸面合同」心智：

1. **分页真相在 Web**，不绑定 WPS 页码；  
2. **只保留翻页**（页底左右箭头），无展开全部；  
3. **纸内页脚打印「第 n 页」**，导出可见；  
4. **按页挂载编辑**；合同详情 + 分享页覆盖，**模板池不改造**；  
5. **导出多张 PNG 与所见页一一对应**。

需求已定稿，可按 §9 进入编码实施。

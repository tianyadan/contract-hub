## 1. 背景与目标

### 1.1 需求来源（产品五则）

| # | 需求摘要 | 当前缺口 |
|---|----------|----------|
| R1 | 文档编辑支持 **键盘左右键** 快速翻页 | 仅有页底 `PageNavigator` 按钮翻页，键盘无效 |
| R2 | **Ctrl+Z 最多 5 次**撤销；现状体感只能撤 1 步 | 代码 `MAX_UNDO_STACK=50`，但快照入栈策略导致有效撤销深度不足 |
| R3 | 分享打开页须同时校验 **客户姓名 + 预留手机号** | V3.4 仅姓名门禁；手机号未参与校验 |
| R4 | 双方确认后，各自视角须看到 **「我已确认」+「对方已确认」** 提醒，且及时同步 | 有确认记录列表与 `confirm-progress` API，但无醒目双视角 Banner，无 WS 推送 |
| R5 | 任一方 **保存版本** 且双方在线时，须提醒对方刷新；刷新须 **保留当前页码** | WS 仅 `presence`，无 `version_saved`；刷新后 `loadDetail` 会重置页码 |

### 1.2 总目标

| 目标 | 验收标准 |
|------|----------|
| 键盘翻页 | 焦点在编辑器（含只读阅览）时，`←`/`→` 翻页；编辑输入区聚焦且未选中文本时不误触 |
| 撤销 5 步 | 连续 5 次独立编辑操作后，可连续 Ctrl+Z 撤销 5 步；第 6 步起丢弃最早快照 |
| 分享双因子 | 姓名 + 手机号与合同档案快照一致方可 `join`；不匹配统一提示「信息有误」 |
| 确认双视角 | 内部/外部页顶展示「您已确认」「对方已确认」状态条；对方确认后 **3s 内** 本端可见 |
| 保存互提醒 | 对方保存后本端弹出非阻塞提醒；用户点「刷新」后仍停在原页码（页码越界则钳制到最后一页） |

### 1.3 范围

| 纳入 | 不纳入 |
|------|--------|
| 合同详情 `DocumentEditor` | 模板池高保真 PDF 预览（V3.5 已覆盖） |
| 外部分享页 `DocumentEditor` | 自动静默刷新正文（避免客户被动翻页） |
| 客户档案姓名/手机号必填校验对齐 | 分享链接短信 OTP 二次验证 |
| WebSocket 扩展消息类型 | 多人（>2）协同冲突合并 |

## 2. 现状基线（代码锚点）

### 2.1 翻页

| 模块 | 现状 |
|------|------|
| `PageNavigator.tsx` | 左右按钮 `onChange(current ± 1)` |
| `DocumentEditor.tsx` | `currentPage` state；`handlePageChange`；`handleEditorKeyDown` **未处理** ArrowLeft/ArrowRight |
| V3.1 | 已约定「纸外翻页条、不进 PNG」 |

### 2.2 撤销

| 模块 | 现状 |
|------|------|
| `DocumentEditor.tsx` | `undoStackRef` / `redoStackRef`；`MAX_UNDO_STACK = 50` |
| 入栈时机 | `pushUndoSnapshot`：Backspace/Delete、部分块操作、`markInputUndoBurst`（输入突发仅 **1 次** 入栈） |
| 用户体感 | 连续打字多次 Ctrl+Z 只能回到输入前一步；格式化/部分快捷键可能未入栈 |

**产品要求**：有效撤销深度 **≤ 5**（非 50），且每步对应一次「可感知编辑动作」。

### 2.3 分享门禁

| 模块 | 现状 |
|------|------|
| `SharePage.tsx` | 门禁仅 `Input` 姓名 → `POST /join { name }` |
| `share_service.go` `Join` | 校验 `name` 非空；**不校验手机号** |
| `contract` 表 | 已有 `customer_name`、`customer_phone` 快照字段 |
| `customer_service.go` | 建档时姓名、手机号均已必填 |
| 合同导入 `ContractImportModal` | 客户电话 **可选**（需与 R3 对齐为必填或关联客户档案） |

### 2.4 双方确认

| 模块 | 现状 |
|------|------|
| `contract_confirm.go` | `requires_dual_confirm`、`has_internal_confirm`、`has_external_confirm` |
| `ContractDetailPage` / `SharePage` | 侧边「确认记录」列表；确认成功仅 `message.success` |
| `usePresence` | 只消费 `type=presence` |
| 缺口 | 发起方确认后不知道对方是否已确认；对方确认后发起方无醒目提示 |

### 2.5 保存与同步

| 模块 | 现状 |
|------|------|
| 保存 API | `POST /contracts/{id}/versions`、`POST /share/{token}/versions` |
| WS Hub | 仅 `presence` / `join` / `leave` |
| 刷新 | `loadDetail` / `loadContract` 全量替换 `documentContent`，`DocumentEditor` 页码归零 |

## 3. 功能设计

### 3.1 R1 — 键盘左右键翻页

#### 3.1.1 交互规则

```text
条件：DocumentEditor 获得焦点（编辑或只读均可）
  ArrowLeft  → 上一页（current > 0）
  ArrowRight → 下一页（current < total - 1）

例外（不翻页，交给浏览器/编辑器默认行为）：
  - 焦点在 contentEditable 且存在非折叠文本选区（用户正在选中文字）
  - 组合键 Alt/Meta/Ctrl/Shift + 方向键
  - 分页计算中 paginating === true
```

#### 3.1.2 实现要点

| 文件 | 改动 |
|------|------|
| `DocumentEditor.tsx` | 在 `handleEditorKeyDown` 增加 ArrowLeft/ArrowRight 分支；调用 `handlePageChange` |
| 可选 | `document` 级 `keydown` 监听（只读且无 contentEditable 焦点时）— **优先在现有 handler 内实现** |
| `PageNavigator.tsx` | 无需改动（行为保持一致） |

#### 3.1.3 无障碍

- 翻页后更新 `aria-live` 或页码区域焦点提示（可选 P2）
- 与 V3.1 页脚「第 n 页」展示一致

### 3.2 R2 — Ctrl+Z 最多 5 次撤销

#### 3.2.1 产品规则

| 规则 | 说明 |
|------|------|
| 最大深度 | `MAX_UNDO_STACK = 5` |
| 一步定义 | 一次「逻辑编辑」：输入突发（debounce 结束）、Backspace/Delete、Enter 拆段、工具栏改样式、表格单元格提交等 |
| 重做 | 保持 Ctrl+Shift+Z / Ctrl+Y；redo 栈在 **新编辑** 时清空 |
| 跨页 | 撤销可改变块内容并触发重分页；尽量保持当前页，若当前页为空则跳到相邻有效页 |

#### 3.2.2 现状问题与修复方向

| 问题 | 修复 |
|------|------|
| 输入仅 `markInputUndoBurst` 入栈 1 次 | 保留突发合并，但 **burst 结束后再入栈当前态** 作为下一步基线（可选） |
| 部分操作未 `pushUndoSnapshot` | 梳理 `commitBlocksUpdate` / 工具栏 / `splitBlockAtCursor` 路径，统一经 `pushUndoSnapshot` |
| 连续撤销后栈空 | UI 无提示即可；`performUndo` 返回 false 时静默 |
| 外部 `documentContent` 替换（保存/刷新） | **清空** undo/redo 栈，避免撤回到旧版本 |

#### 3.2.3 实现要点

```typescript
// DocumentEditor.tsx
const MAX_UNDO_STACK = 5

// documentContent 自外而内更新且非本组件编辑引起时：
undoStackRef.current = []
redoStackRef.current = []
```

### 3.3 R3 — 分享页姓名 + 手机号双因子门禁

#### 3.3.1 业务规则

```text
打开 /share/{token}
  → 仍不暴露合同名称/正文
  → 门禁表单：客户姓名 + 预留手机号（均为必填）
  → POST /join { name, phone }
  → 服务端比对 contract.customer_name、contract.customer_phone（归一化后）
       一致 → 创建/更新 collaborator，返回成功
       不一致 → 403/400「姓名或预留手机号不正确」（不透露哪一项错）
  → sessionStorage 写入 lshc_share_name_{token}、lshc_share_phone_{token}
  → 后续 API / WS 携带姓名；手机号仅 join 时用，或 WS 查询参数可选携带用于审计
```

#### 3.3.2 数据归一化

| 字段 | 规则 |
|------|------|
| 姓名 | `TrimSpace`；全角空格转半角；忽略连续空格 |
| 手机号 | 仅保留数字；中国大陆 11 位；合同存档与输入统一格式化后比较 |

#### 3.3.3 合同与客户档案对齐

| 场景 | 要求 |
|------|------|
| 客户档案创建/编辑 | 已必填（`customer_service`）— 保持 |
| 从客户创建合同 | 写入 `customer_name` + `customer_phone` 快照 |
| 合同导入未关联客户 | **阻断分享** 或 **创建分享前校验** 合同已具备姓名+手机号；分享按钮旁提示「请先完善客户信息」 |
| 历史合同缺手机号 | 分享创建时前端+后端校验；缺失则 `ErrShareGateIncomplete` |

#### 3.3.4 API 变更

| 方法 | 路径 | 变更 |
|------|------|------|
| POST | `/api/share/{token}/join` | Body 增加 `phone`；校验与合同快照一致 |
| POST | `/api/contracts/{id}/share` | 创建分享前校验 `customer_name`、`customer_phone` 非空 |
| GET | `/api/share/{token}` | 可增加 `requires_phone_gate: true`（不返回真实手机号） |

**Join 请求体：**

```json
{
  "name": "张三",
  "phone": "13800138000"
}
```

#### 3.3.5 前端

| 文件 | 改动 |
|------|------|
| `SharePage.tsx` | 门禁增加手机号 `Input`；校验 11 位；存储双 session key |
| `shareApi.ts` | `joinShare(token, name, phone)`；各 `withName` 可保持不变（join 后仍以 collaborator_name 标识） |
| `usePresence.ts` | join 前需姓名；逻辑不变 |
| `ContractDetailPage` 分享弹窗 | 缺手机号时禁用分享并提示 |

### 3.4 R4 — 双方确认状态双视角提醒（实时）

#### 3.4.1 展示设计

在 `OnlinePresenceBar` **下方** 增加 `ConfirmStatusBanner`（合同详情 + 分享页复用）：

```text
┌─────────────────────────────────────────────────────────┐
│ ✓ 您已确认当前版本（V3）    │  ⏳ 等待外部协作者确认      │  ← 内部用户视角（仅自己确认）
├─────────────────────────────────────────────────────────┤
│ ✓ 您已确认当前版本（V3）    │  ✓ 外部协作者已确认         │  ← 内部用户视角（双方已确认）
├─────────────────────────────────────────────────────────┤
│ ✓ 您已确认当前版本（V3）    │  ⏳ 等待内部用户确认        │  ← 外部用户视角
└─────────────────────────────────────────────────────────┘
```

- `requires_dual_confirm === false`：仅展示单行「您已确认 / 尚未确认」
- 合同 `status=3`（已锁定）：Banner 变为绿色「双方已确认，合同已锁定」

#### 3.4.2 数据来源

| 时机 | 行为 |
|------|------|
| 进入页面 | `GET confirm-progress` + `GET confirmations` |
| 本端确认成功 | 乐观更新 Banner + 重新拉取 |
| 对方确认 | **WebSocket 推送**（见 §4）或轮询兜底（15s，仅 WS 断开时） |

#### 3.4.3 WebSocket 扩展

确认/取消确认成功后，向合同房间广播：

```json
{
  "type": "confirm_progress",
  "data": {
    "version_id": 123,
    "has_internal_confirm": true,
    "has_external_confirm": false,
    "requires_dual_confirm": true,
    "contract_status": 2
  }
}
```

前端 `useCollaboration`（新 Hook，或扩展 `usePresence`）合并处理 `presence` + `confirm_progress` + `version_saved`。

#### 3.4.4 后端触发点

| 位置 | 动作 |
|------|------|
| `contract_confirm.go` `ProcessConfirmation` 成功 | `hub.BroadcastConfirmProgress(contractID, ...)` |
| `FinalizeConfirmWithPdfArchive` 完成 | 同上，`contract_status=3` |
| 可选 | 取消确认（若未来支持）同步广播 |

### 3.5 R5 — 保存后在线互提醒 + 保页刷新

#### 3.5.1 流程

```text
用户 A 点击「保存版本」且成功
  → 后端写库完成
  → WS 广播 { type: "version_saved", data: { version_no, saved_by, saved_by_role, version_id } }
  → 用户 B（在线且非保存者）顶部 Alert：
        「{name} 已保存新版本 V{n}，请刷新以查看最新内容」
        [立即刷新] [稍后]
  → B 点击「立即刷新」：
        1. 记录 currentPage = editorRef.getCurrentPage?.() ?? sessionStorage
        2. loadDetail / loadContract
        3. 恢复 currentPage（钳制到 [0, totalPages-1]）
        4. 若有未保存本地修改 → 弹窗确认是否丢弃
```

**禁止**：对方保存后自动静默替换正文（客户可能正在阅读某一页）。

#### 3.5.2 DocumentEditor 扩展

```typescript
export interface DocumentEditorHandle {
  getExportRoot: () => HTMLElement | null
  preparePagesForExport: () => Promise<HTMLElement[]>
  getPageCount: () => number
  getCurrentPage: () => number      // 新增
  setCurrentPage: (index: number) => void  // 新增
}
```

页码持久化 key（可选双保险）：

```text
lshc_editor_page_{contractId|shareToken}
```

#### 3.5.3 后端

| 位置 | 动作 |
|------|------|
| `ContractService.SaveVersion` | 成功后 `hub.BroadcastVersionSaved` |
| `ShareService.ShareSaveVersion` | 同上 |
| `ws/hub.go` | 新增广播方法；消息类型 `version_saved` |

#### 3.5.4 前端组件

| 组件 | 职责 |
|------|------|
| `StaleContentBanner.tsx` | 展示「有新版本」提醒条 |
| `useCollaboration.ts` | 统一 WS：presence + confirm_progress + version_saved |
| `ContractDetailPage` / `SharePage` | 接入 Banner；刷新时保页 |

#### 3.5.5 边界

| 场景 | 处理 |
|------|------|
| 仅自己在线 | 不展示提醒 |
| 保存者本端 | 不提醒自己 |
| 查看历史版本 | 禁用刷新条或提示「请切回当前版本」 |
| 合同已锁定 | 无保存提醒；确认 Banner 仍展示 |

## 4. WebSocket 协议汇总（V3.6 扩展）

在 V3.4 `presence` 基础上扩展：

| type | 方向 | 载荷 | 说明 |
|------|------|------|------|
| `presence` | S→C | `{ list: [{ name, role }] }` | 保持 1s 全量同步 |
| `join` / `leave` | S→C | `{ data: { name, role } }` | 保持 |
| `confirm_progress` | S→C | 见 §3.4.3 | 确认状态变更 |
| `version_saved` | S→C | `{ version_no, saved_by, saved_by_role, version_id }` | 新版本保存 |

**不增加**客户端→服务端业务消息（仍只读+心跳）；广播由 HTTP 保存/确认 Handler 触发。

| 历史合同无手机号 | 分享前强制补全客户信息；批量数据脚本可选 |
| WS 广播与 Service 循环依赖 | Hub 以接口注入 Service，或轻量 `event.Bus` |
| 保页刷新后页数变少 | `min(savedPage, newTotal-1)` |
| 手机号格式不一 | 统一 `normalizePhone` 再比较 |
| 撤销 5 步与输入突发合并冲突 | 产品确认：突发内多字符仍算 1 步 |

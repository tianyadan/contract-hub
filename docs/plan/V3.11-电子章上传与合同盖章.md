## 1. 背景与目标

### 1.1 问题

合同需支持电子盖章；内部希望一套章库多合同复用；外部若上传章图，一旦入库或进版本 JSON，易造成**章泄露**与存储浪费。因此外部采用「上传 → 选页选位 → 烧录 → 丢弃」；确认后在线侧不再保留任何章配置。

### 1.2 需求

| # | 需求 | 说明 |
|---|------|------|
| R1 | 内部章库 | 「合同设置 → 电子章」统一维护；支持多枚、命名、默认、删除 |
| R2 | 手机上传 | **手机与桌面均支持**上传电子章（内部设置页；外部盖章流程内的临时上传） |
| R3 | 内部跨合同烧录 | 内部用章库中的章，对**不同合同**可随时选页、选位置烧录（预览放置 + 导出/确认烧进 PDF） |
| R4 | 外部即烧即弃 | 外部上传章后，**由用户选择烧录在哪一页、哪个位置**；章图与落章信息**不存储**（不进章库、不进 OSS 持久对象、不进 `document_content` 长期字段） |
| R5 | 确认后清配置 | 合同确认成功后，清除文档内电子章配置（若内部协作期曾写入临时 seals），防止章 URL/坐标残留泄露 |
| R6 | 导出一致 | 烧录进草稿/终稿 PDF 的视觉与用户所选页、位一致 |

### 1.3 非目标

| 项 | 说明 |
|----|------|
| CA / 数字证书签章 | 仍为业务图片烧录 |
| 外部长期章库 / 跨合同复用章 | 明确禁止，防泄露 |
| 确认后网页回放盖章层 | 只保留终稿 PDF 中的像素 |
| 外部章图服务端落盘「方便下次再用」 | 与防泄露冲突，不做 |

### 1.4 已确认产品规则

| # | 议题 | 结论 |
|---|------|------|
| D1 | 内部章库 | **用户级**，合同设置统一维护；**所有合同**可随时选用烧录 |
| D2 | 外部盖章 | **当前合同一次性**：上传 → **选页 + 选位置** → **烧录** → **不存储** |
| D3 | 手机 | **支持上传与盖章流程**（触控选页/拖位置；设置页亦适配） |
| D4 | 确认后 | **清除**在线侧电子章配置；内部**章库保留**；外部无库可清 |
| D5 | 防泄露原则 | 外部章图仅存浏览器内存（`File` / `blob:` / `ObjectURL`）；导出截图用完即 `revoke`；不写分享接口可持久拉取的章资源 |
| D6 | 坐标 | 页内百分比 `x_ratio` / `y_ratio` + `page_index` |
| D7 | 内部协作期是否写入 seals | **允许短期写入**便于多端预览；**确认后必须 Strip**。若产品要求内部也「只烧不存」，可改为与外部相同的会话态（见 §4.3 选项） |

**默认实施建议（D7）**：

- **内部**：章库持久；合同上可放置预览并写入 `seals`（协作可见）；确认后 Strip 文档 seals。  
- **外部**：**绝不**写入 DB/OSS/版本 JSON；仅会话态放置，在「导出 PDF / 确认合同」当次烧录。

## 2. 用户流程

### 2.1 内部（含手机）

```text
【维护】合同设置 → 电子章 → 上传（相册/文件）→ 命名 / 设默认
【烧录】打开任意未锁定合同 →「盖章」→ 选章库中的章
       → 选页（或当前页）→ 拖到目标位置 / 缩放
       → 预览满意后：保存版本（可选，协作期）或直接导出/确认
       → 确认成功：终稿 PDF 含章；文档 seals 清除；章库仍在，下份合同继续用
```

### 2.2 外部（含手机）— 即烧即弃

```text
打开当前合同分享链接 → 门禁通过
  →「盖章」→ 本机上传电子章（不上传到服务器章库）
  → 明确步骤：
       1) 选择烧录页码（第 N 页）
       2) 在纸面上点选/拖动位置（可缩放）
       3) 确认烧录（随「导出 PDF」或「确认合同」一次完成）
  → 章图仅留在本次页面内存；关闭页面或完成后丢弃
  → 服务端不保存外部章文件；document_content 不持久化外部 seals
  → 合同确认后：无外部章配置可清；终稿 PDF 已含章像素
```

### 2.3 确认后防泄露

```text
终稿 PDF 上传成功
  → Strip：清空所有版本 document_content.seals（内部协作期残留）
  → 删除任何合同级临时 OSS 章对象（若误建则删；外部路径本就不该有）
  → 在线纸面不再叠章；文案引导下载终稿
  → 内部用户章库：保留（非本合同泄露面；仍仅本人 JWT 可管）
```

## 4. 方案设计

### 4.1 角色对照（防泄露视角）

| | 内部 | 外部 |
|--|------|------|
| 上传入口 | 合同设置（桌面+手机） | 当前合同盖章弹层（桌面+手机） |
| 章图存储 | OSS + `user_seal_asset` | **不存储**（仅内存） |
| 跨合同 | ✅ 随时烧录到不同合同 | ❌ 仅当前分享合同 |
| 落章配置 | 协作期可写 `seals`；确认后清除 | **不写库**；仅当次烧录参数 |
| 确认后 | 清文档 seals；章库保留 | 无持久配置；PDF 已烧 |

### 4.2 内部章库模型

表 `user_seal_asset`（同前，用户级）。  
OSS：`users/{userId}/seals/{sealId}/{uuid}.png`  
API：`GET/POST/PUT/DELETE /api/settings/seals`（JWT）。  
设置页：**响应式**，手机可完整上传与管理。

### 4.3 两种「烧录」会话态

#### 4.3.1 内部 `DocumentSeal`（可短持久）

```ts
interface DocumentSeal {
  id: string
  asset_id: number
  image_url: string      // 章库 URL；确认后整段删除，降低泄露面
  page_index: number
  x_ratio: number
  y_ratio: number
  scale: number
  placed_by: 'internal'
}
```

确认后 Strip，不在已锁定合同 JSON 中保留。

#### 4.3.2 外部 `EphemeralSeal`（仅前端内存）

```ts
interface EphemeralSeal {
  id: string
  /** 本地 ObjectURL 或 ImageBitmap，禁止提交给 saveVersion */
  object_url: string
  file_name?: string
  page_index: number     // 用户选择的烧录页
  x_ratio: number        // 用户选择的位置
  y_ratio: number
  scale: number
}
```

- `prepareSaveDocumentContent` / 保存版本：**剥离**任何 ephemeral 字段，禁止进 API。  
- 导出/确认：把 ephemeral 章画进 export-host 对应页 → 截图 → PDF → `URL.revokeObjectURL`。  
- 刷新分享页：外部需重新上传（可接受；符合不存储）。

### 4.4 外部交互：强制「选页 + 选位」

推荐分步 UI（手机友好）：

1. **上传**：拍照/相册/文件，校验 PNG/JPEG、≤2MB  
2. **选页**：页码 Stepper / 缩略翻页，「盖在第 N 页」  
3. **选位**：该页预览上拖章或点击落点；显示准心/比例  
4. **确认烧录**：绑定到「导出 PDF」或「确认合同」按钮（文案写明：章仅写入 PDF，不会保存在服务器）

禁止：静默上传到 OSS「稍后再盖」。

### 4.5 内部交互：统一维护 + 随时烧录

1. 设置页维护章库（手机可上传）  
2. 合同工具栏「盖章」→ 选库内章 → 当前页或指定页 → 拖位置  
3. 可对合同 A/B/C 重复使用同一章  
4. 导出/确认时烧录；确认后清文档 seals  

### 4.6 确认后 Strip（防泄露）

| 清除 | 保留 |
|------|------|
| 各版本 `document_content.seals` | 终稿 PDF（含章像素） |
| 合同目录下误传的 `contracts/{id}/seals/*` | 内部 `user_seal_asset` 章库 |
| 前端 ephemeral ObjectURL | — |

顺序：**终稿上传成功 → 再 Strip**（失败则保留内部 seals 以便重试；外部本就未落库）。

### 4.7 导出实现要点

| 点 | 说明 |
|----|------|
| 内部 | export-host 用章库 URL 渲染（注意 CORS） |
| 外部 | export-host 用 `blob:` / 内存图渲染，**同域无 CORS 问题** |
| 多页 | 仅用户选中的 `page_index` 贴章 |
| 手机 | 导出仍走现有前端截图链路；注意内存与页数 |

### 4.8 API 边界（防泄露）

| 接口 | 内部 | 外部 |
|------|------|------|
| `/api/settings/seals*` | ✅ | ❌ 403/不存在 |
| `saveContractVersion` 带 seals | ✅（仅 internal 结构） | ❌ 忽略或拒绝含 image 二进制的 seals |
| 分享 save | 正文可变；**丢弃**客户端传来的 seals |
| 确认/导出 | 截图结果上传 PDF；不接收外部章 multipart 落库 |

若外部确认必须服务端合成：也只接受「当次 multipart 章图 + page/x/y」在内存中合成 PDF，**处理完不写盘**（进阶方案；优先纯前端截图烧录更贴现有架构）。

## 5. 分期实施

### Phase A

1. 内部设置页章库 CRUD（**含移动端上传 UI**）  
2. 内部合同盖章：选章、选页、拖位、导出烧录  
3. 外部分享：临时上传 → 选页选位 → 确认/导出烧录 → 不落库  
4. 确认成功 Strip 内部 seals

1. 手机拖拽/`fitScale` 手感优化；点按落点兜底  
2. 外部步骤引导与防泄露文案  
3. 历史数据 GC（若曾写入 seals）  

### Phase C

旋转、多章、仅 owner 开关等。

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| 外部章被误传到 OSS | 代码路径隔离；评审禁止 share 上传走 settings/OSS |
| 外部刷新丢失未烧录的章 | 文案提示「请一次完成盖章并确认/导出」 |
| 先 Strip 后 PDF 失败 | 先上传终稿成功再 Strip |
| 手机选位不准 | 选页 + 大号拖动手柄；支持点击落点微调 |
| 内部 seals 确认前被分享拉取造成章 URL 暴露 | 分享 token 下发的 image_url 用短时签名；确认后删除 seals 降泄露窗口 |
| 内存章图过大 | 前端压缩至边长 ≤1500px 再预览/烧录 |

## 9. 决策结论（已确认）

1. **手机支持**上传电子章（内部设置 + 外部临时上传）。  
2. **外部**：上传后由用户选择**烧录页与位置**，**不存储**章图与配置，防泄露。  
3. **内部**：合同设置统一维护章库，**可对任意合同随时烧录**。  
4. **合同确认后**：清除在线电子章配置；以终稿 PDF 为准；内部章库保留。

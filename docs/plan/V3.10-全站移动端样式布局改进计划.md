## 1. 问题现象（产品视角）

### 1.1 用户反馈 / 截图结论

手机访问**登录后内部系统**（例如合同详情）时：

| 现象 | 影响 |
|------|------|
| 左侧菜单常驻占宽约 220px | 正文区极窄，标题/编号竖排换行，按钮被裁切 |
| 「保存版本 / 分享」挤在顶栏 | 无法可靠点击 |
| 格式工具栏碎成一截 | 无法正常编辑 |
| 合同纸面与侧栏信息叠在狭缝中 | 无法正常阅览 |

对比：

| 页面类型 | 手机可用性 |
|----------|------------|
| 登录页 `/login` | ✅ 可用（隐藏品牌侧栏，单栏表单） |
| 外链分享 `/share/:token` | ⚠️ V3.9 已做适配，仍有收尾空间 |
| 公开验真 `/verify/:code` | ✅ 基本可用 |
| 登录后主布局内全部页面 | ❌ 基本不可用（壳层未适配） |

**根因一句话**：登录后统一套了桌面版 `MainLayout`（固定侧栏），内部页面再叠桌面双栏，窄屏没有「抽屉导航 + 操作底栏 + 信息折叠」策略。

## 3. 技术约定

### 3.1 统一断点

| Token | 宽度 | 用途 |
|-------|------|------|
| `mobile` | `≤767px` | 手机：Drawer、Dock、单栏 |
| `tablet` | `768–991px` | 平板：侧栏可收起或单列堆叠 |
| `desktop` | `≥992px` | 现有桌面布局 |

废弃散落断点（实施时收敛）：Login `720/960`、OnlinePresence `768`、ChangeInspect `640` → 映射到上表。

### 3.2 Hook

- 已有：`frontend/src/hooks/useMediaQuery.ts` → `useIsMobile()`（767）
- 新增建议：`useIsTablet()`（≤991）、可选 `BREAKPOINTS` 常量导出供 CSS/`less` 注释对齐
- **强制**：MainLayout、ContractDetailPage、TemplateDetailPage 接入 `useIsMobile`

### 3.3 设计原则

1. **主壳先修**：不改 MainLayout，内部页再怎么调都会被侧栏吃宽。  
2. **主任务单栏**：编辑区优先；版本/确认等次要信息进 Tabs / Drawer / BottomSheet。  
3. **操作贴拇指**：保存 / 确认 / 导出 / 分享 → 底部固定 Dock（复用 Share 模式）。  
4. **纸面用 CSS scale**：测量与导出仍用完整分辨率（V3.9 已定，禁止用缩小 layout 做分页）。  
5. **触控 ≥44px**；预留 `safe-area-inset-bottom`。  
6. **向登录页学习**：次要视觉可隐藏，主表单/主文档占满宽度。

## 5. 分模块差距与方案

### 5.1 MainLayout（全局壳）— P0 · Broken

| 项 | 说明 |
|----|------|
| 路径 | `layouts/MainLayout.tsx`、`main-layout.css` |
| 现状 | `Sider width={220}` 常驻；仅桌面折叠；Header 长标题；Content `padding: 24px`；无 Drawer、无 `useIsMobile` |
| 方案 | ≤767：默认关闭 Sider → **汉堡 + Ant Drawer 导航**；Header 仅 Logo + 短标题 + 用户；Content padding `12px`；合同/模板详情可设 `fullBleed` 减边距 |
| 验收 | 375 宽下内容区可用宽度 ≥ 约 350px（不再被 220 侧栏挤占） |

**建议信息架构（手机）：**

```
┌─ Header: [☰] Logo  短标题 …… Avatar ─┐
│  <Outlet Content（全宽）>                    │
└──────────────────────────────────────────┘
Drawer: 首页 / 客户 / 模板 / 合同 / 设置 / 统计
```

### 5.2 ContractDetailPage（内部合同编辑）— P0 · Broken

| 项 | 说明 |
|----|------|
| 路径 | `pages/ContractDetail/ContractDetailPage.tsx`、`contract-detail.css` |
| 现状 | `Col xs=24 lg=16/8` 虽会堆叠，但顶栏塞满操作按钮；无 mobile dock；右侧 Tabs 永远在编辑器下方；再被 MainLayout 挤压 |
| 方案 | 对齐 Share：① `useIsMobile`；② 顶栏只留返回 + 标题省略 + 状态 Tag；③ **底部 Dock**：保存 / 确认 / 导出 / 分享（或「更多」）；④ 版本/历史/确认 → Tabs 或 Drawer；⑤ 与 MainLayout `fullBleed` 配合 |
| 验收 | 可不依赖横向滚动完成：翻页、改字、保存、分享 |

### 5.3 DocumentEditor + FormatToolbar — P0 · Partial

| 项 | 说明 |
|----|------|
| 路径 | `DocumentEditor.tsx`、`doc-editor.css`、`FormatToolbar.tsx`、`format-toolbar.css` |
| 已有 | `fitScale` 纸面缩放；767 减 padding；工具栏横向滚动；翻页触控加大 |
| 问题 | Floating 工具栏易被裁切；按钮偏小（约 28px）；键盘顶起时遮挡 |
| 方案 | 移动端：**禁用或弱化 floating**，统一用 sticky 顶栏 / 底栏 FormatToolbar；常用组（加粗/颜色/对齐）外露，「更多」收纳字体字号；监听 `visualViewport` 避免被键盘挡住 |
| 验收 | 竖屏可完成加粗、改色、对齐；键盘弹出后仍能点到保存 Dock |

## 8. 风险与对策

| 风险 | 对策 |
|------|------|
| 纸面 scale 后点选精度下降 | 仅显示层 scale；保持现逻辑；必要时提供「放大阅读」 |
| 软键盘顶起遮挡工具栏/Dock | `visualViewport` resize 调整 bottom |
| Drawer 与编辑失焦冲突 | 打开 Drawer 前 blur 编辑器 |
| PC 回归 | ≥992 保持现布局；用桌面宽度冒烟测分享/详情 |

## 11. 决策结论（给产品/研发对齐）

1. **先改壳（MainLayout）再改页**——截图中的「极丑、不能编」首先是侧栏吃宽，不是单纯编辑器丑。  
2. **内部详情复用分享页已验证的 Dock + Tabs 模式**，避免两套交互。  
3. **分享页不推倒重来**，只做避让与信息密度收尾。  
4. 列表与后台管理页放 P1/P2，保证先打通「手机看合同 / 改合同 / 外链协作」主路径。

## 1. 背景与问题

### 1.1 用户反馈

保存版本后，右侧「版本记录」只有版本号与修改说明，**看不到具体改了什么**；若仅调整加粗、字号、颜色等样式，更是完全没有变更明细。用户期望：

1. 每次保存版本，**内容变更**（增删改段落/表格）有记录；
2. **样式变更**（块级 + 选区 run 级）有记录；
3. 记录应可读、可追溯，便于协作与审计；
4. 不影响现有编辑体验（分页位置、样式工具栏、PNG 导出等）。

### 1.2 根因说明（非前端保存逻辑回归）

| 现象 | 真实原因 |
|------|----------|
| 保存后只有版本、无变更记录 | V3 实施时，`SaveVersion` / `ShareSaveVersion` **刻意传入 `nil` 变更列表**，`change_count` 固定为 0 |
| 时间线只显示版本备注 | `ChangeTimeline` 在 `versions.length > 0` 时**只渲染版本列表**，不再展示 `contract_change` |
| 与「去掉 loadDetail」无关 | 近期保存优化仅避免编辑器卸载；**变更记录本就不会写入**，不是该改动导致 |

相关代码（当前行为）：

```go
// backend/internal/service/contract_service.go — SaveVersion
if err := s.contracts.CreateVersionWithChanges(ctx, input.ContractID, version, nil, audit); err != nil {
```

V3 架构文档 6.3 节将块级 diff **标记为停止写入**，属于**产品能力回退**，需在 V3.2 正式恢复并扩展。

### 1.3 与 V3 原则的关系

| V3 原则 | V3.2 如何兼容 |
|---------|----------------|
| 网页即真相 | Diff 基于 **前端提交的 `document_content` JSON**，与 PNG 所见同源 |
| 不依赖 Python 渲染 | Diff **在 Go 后端实现**（或可选前端预计算 + 后端校验），不恢复 document-engine `/diff` 为必经链路 |
| 版本快照完整 | 继续全量存 `contract_version.document_content`；变更表为 **增量审计视图** |
| 2C2G / 简单栈 | 纯 JSON 比较，无 OCR、无截图对比 |

## 2. 目标与非目标

### 2.1 目标（Must）

| ID | 目标 |
|----|------|
| G1 | 每次 `POST .../versions` 成功，**自动写入** `contract_change`，`change_count` 为实际条数 |
| G2 | 覆盖 **块新增 / 删除 / 文本修改**（按 `block.id` 对齐） |
| G3 | 覆盖 **块级样式变更**（`block.style`：字体、字号、对齐、行距、缩进、底纹等） |
| G4 | 覆盖 **run 级样式变更**（`block.runs[]` 局部加粗、颜色、下划线等） |
| G5 | 覆盖 **表格内容变更**（`rows` 二维数组 diff，按块 id） |
| G6 | 右侧时间线：**版本 + 该版本下的变更明细** 分层展示，可读中文描述 |
| G7 | 外部分享保存版本 **同一套 diff 逻辑** |
| G8 | 与现有编辑器行为兼容：保存后 **保持当前页**、不强制 `loadDetail` 全页重载 |

### 2.2 非目标（Out of Scope）

| 项 | 说明 |
|----|------|
| 像素级 / PNG 图像 diff | 不做截图对比 |
| 恢复 Python document-engine `/diff` 为生产依赖 | 可作为参考实现，非必选 |
| 实时协同 OT 操作流 | 仍以「保存版本」为 diff 边界 |
| 自动合并冲突 | 保持现有「后保存覆盖」 |
| 条款编号 `clause_no` 自动推断 | 无 `source_ref` 时可为空，仅展示 block 摘要 |

## 3. 变更分类设计

### 3.1 沿用并扩展 `change_type`

现有库表：`0=新增 1=删除 2=修改`（`sql/init.sql`）。

**方案（推荐）**：保留 `change_type` 三态表示 **块级生命周期**，用 `change_reason` + 结构化 JSON 区分子类型，避免改表：

| change_type | 含义 | `old_content` / `new_content` 约定 |
|-------------|------|-----------------------------------|
| 0 新增 | 新块出现 | `new_content` = 块文本摘要或表格首行摘要；`old_content` 空 |
| 1 删除 | 块被删 | `old_content` = 删除前摘要 |
| 2 修改 | 块仍存在但内容或样式变 | 见下表 |

**`change_type = 2` 子类型**（写入 `change_reason` 前缀或 JSON 字段）：

| 子类型 code | 说明 | 记录方式 |
|-------------|------|----------|
| `text` | 纯文本变化 | `old_content` / `new_content` 为文本摘要（超长截断 500 字） |
| `style_block` | 块级样式 | `old_content` / `new_content` 为 **样式 diff JSON** |
| `style_run` | run 级样式 | 同上，含 offset 范围 `[start,end)` |
| `table` | 表格单元格 | JSON：`{ "rows_diff": [...] }` |
| `structure` | 块顺序 / 分页标记 | `page_break_before`、`order` 变化 |

**备选（P2）**：新增列 `change_subtype VARCHAR(32)`，迁移脚本 `migrate_v4.sql`，查询更清晰。

### 3.2 样式 Diff 粒度

对 `BlockStyle` 与 `DocumentRun.style` 做 **键级 diff**：

```json
{
  "bold": { "old": true, "new": false },
  "font_size": { "old": 10.5, "new": 12 },
  "color": { "old": "000000", "new": "C00000" }
}
```

展示层翻译为：

> 块 `b-xxx`：加粗 是→否；字号 10.5pt→12pt；颜色 #000000→#C00000

run 级额外带：

```json
{
  "range": { "start": 12, "end": 28 },
  "text_preview": "人民币伍佰元",
  "style_diff": { "underline": { "old": false, "new": true } }
}
```

### 3.3 块对齐策略

1. 主键：**`block.id`**（编辑器稳定 id，`newBlockId()` 生成）。
2. 新增块：`id` 仅出现在新版本 → `change_type=0`。
3. 删除块：`id` 仅出现在旧版本 → `change_type=1`。
4. 同 id 比较：`text`、`runs`、`style`、`rows`、`type`、`page_break_before`。
5. **不做**跨 id 的「移动检测」（P2 可选）：order 变化记为 `structure` 修改。

## 4. 技术方案

### 4.1 Diff 执行位置

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| **A. Go 后端 SaveVersion 时 diff** | 单一真相、防篡改、分享/内部一致 | 需实现 `documentdiff` 包 | **推荐 P0** |
| B. 前端 diff 后随请求提交 | 实现快 | 可被绕过、双端逻辑重复 | 仅作调试 |
| C. 恢复 Python `/diff` | 曾有实现 | 多服务、V3 已降级 | 不推荐 |

### 4.2 Go 模块结构（建议）

```text
backend/internal/documentdiff/
  types.go          # 与前端 DocumentContent 对齐的结构体
  compare.go        # Compare(old, new) []ChangeRecord
  style_diff.go     # diffBlockStyle, diffRuns
  text_diff.go      # 文本摘要、表格 diff
  describe.go       # 生成人类可读 change_reason
```

核心接口：

```go
type ChangeRecord struct {
    ChangeType   int8   // 0/1/2
    BlockID      string
    ClauseNo     string // 可选：从 source_ref.index 推导
    OldContent   string // 文本摘要或 JSON
    NewContent   string
    ChangeReason string // 如 "style_block: 加粗 是→否"
}

func CompareDocuments(oldDoc, newDoc *DocumentContent) []ChangeRecord
```

### 4.3 接入 SaveVersion

```text
旧版本 JSON (detail.Version.DocumentContent)
        ↓
   documentdiff.Compare(old, new)
        ↓
[]ContractChange（填充 from_version_id / to_version_id / operator）
        ↓
CreateVersionWithChanges(ctx, contractID, version, changes, audit)
        ↓
SaveVersionResult.ChangeCount = len(changes)
```

`ShareSaveVersion` 同样接入。

### 4.4 性能与体积

| 项 | 策略 |
|----|------|
| 大合同（500+ 块） | 纯内存 JSON 比较，预计 <50ms，可接受 |
| `old_content`/`new_content` 过长 | 文本截断 500 字；完整样式 diff JSON 限制 8KB/条 |
| 无变更保存 | 前端已拦截；后端若收到相同 JSON，`changes` 为空数组 |

## 6. 前端改造

### 6.1 ChangeTimeline（核心）

当前逻辑：`hasVersions` 时 **只显示版本**，忽略 `changes`。

**目标 UI**：

```text
▼ V3  张三  08-31 21:30
    修改说明：调整付款条款格式
    ├─ [修改] 段落 b-12：文本「…」→「…」
    ├─ [样式] 段落 b-12：加粗 是→否；字号 12pt→10.5pt
    └─ [新增] 段落 b-45：「补充条款…」
▼ V2  李四  08-30 18:00
    …
```

实现要点：

1. 按 `to_version_id` 将 `changes` **归组到对应版本**下方；
2. `change_type` 配色：新增绿 / 删除红 / 修改蓝（恢复 README 描述）；
3. 解析 `change_reason` 或 JSON，展示样式变更中文；
4. 版本无变更时仅显示修改说明。

### 6.2 保存流程（保持 V3.2 已修行为）

```text
保存 → blur 同步 DOM → POST versions
     → 更新 originalSnapshot + version_no（不 loadDetail）
     → loadChangesAndVersions() 刷新时间线
```

**不要**恢复 `loadDetail()` 全量重载（避免跳回第一页）。

### 6.3 类型定义

扩展 `ContractChange`（`frontend/src/types/contract.ts`）：

```ts
export interface ContractChange {
  // ...现有字段
  change_subtype?: 'text' | 'style_block' | 'style_run' | 'table' | 'structure'
  change_reason?: string
}
```

## 8. 测试计划

### 8.1 后端单测

| 用例 | 输入 | 期望 |
|------|------|------|
| T1 新增段 | 多 1 个 block | 1 条 type=0 |
| T2 删除段 | 少 1 个 block | 1 条 type=1 |

### 8.2 前端 E2E（手工）

1. 第 5 页改字保存 → 仍在第 5 页，时间线有记录；
2. 选中文字加粗再保存 → 样式记录出现；
3. 再取消加粗保存 → 记录「加粗 是→否」；
4. 分享链接协作者保存 → 内部时间线可见变更。

## 9. 风险与对策

| 风险 | 对策 |
|------|------|
| 样式继承（块级 bold + run）导致 diff 噪声 | 比较 **有效样式**（块+run 合并后再 diff） |
| `old_content` 过大 | 截断 + 仅存 diff 键 |
| 旧 V1/V2 数据无 block id | 按 order 回退对齐（P2） |
| 与撤销栈无关 | Diff 仅在保存时做一次 |

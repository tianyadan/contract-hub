## 1. 背景与问题

### 1.1 用户反馈

| 现象 | 影响 |
|------|------|
| 保存版本后右侧有变更明细，但不知道在第几页 | 无法快速复核 |
| 点击变更内容无反应 | 无法定位到纸面 |
| 列表仅有摘要文字，纸面上看不到红绿对比 | 不如 Git Diff 直观 |

期望：**像 Git 一样**，点一条变更 → 跳到改动位置 → 用红/绿标出删改与新增，且基于该次版本改动（`from_version` → `to_version`）。

### 1.2 现状能力盘点

| 能力 | 现状 | 结论 |
|------|------|------|
| 变更落库 | `contract_change` 已有 `block_id`、`change_type`、`old_content`、`new_content`、`change_reason`、`from/to_version_id` | **定位主键已具备** |
| 页码落库 | **无** `page_index`；页码由前端测量分页实时计算 | **不应存页码**（字体/边距变化会失效） |
| 时间线 UI | `ChangeTimeline` 只展示，**无点击回调** | 需加交互 |
| 编辑器跳转 | `DocumentEditorHandle` 有 `setCurrentPage`；内部有 `findPageIndex(pageIds, blockId)` | **缺对外 `jumpToBlock`** |
| 纸面 Diff | 时间线 CSS 有红/绿文字；编辑区 **无** `<ins>`/`<del>` 覆盖层 | 需新增 |
| Diff 粒度 | 后端按块比对，文本为整段截断字符串；`Subtype` 未落库 | 行内红绿可前端 LCS；样式类变更单独处理 |

相关路径：

| 层 | 路径 |
|----|------|
| 时间线 | `frontend/src/components/contract/ChangeTimeline.tsx` |
| 详情页 | `frontend/src/pages/ContractDetail/ContractDetailPage.tsx` |
| 分享页 | `frontend/src/pages/Share/SharePage.tsx` |
| 编辑器 | `frontend/src/components/contract/DocumentEditor.tsx` |
| 分页工具 | `frontend/src/utils/paginateDocument.ts` → `findPageIndex` |
| 类型 | `frontend/src/types/contract.ts` → `ContractChange` |
| Diff 后端 | `backend/internal/documentdiff/` |
| 表 | `sql/init.sql` → `contract_change` |

## 2. 目标与非目标

### 2.1 目标（Must）

| ID | 目标 |
|----|------|
| G1 | 变更条目可点击（或显式「定位」按钮），跳转到对应 **页 + 块** |
| G2 | 跳转后块级高亮闪烁/描边，便于识别落点 |
| G3 | 文本类变更：在目标块上展示 **红删 / 绿增** 行内 Diff（Git 风格） |
| G4 | Diff 内容以该条记录的 `old_content` / `new_content`（或 from/to 版本快照中该 `block_id` 全文）为准 |
| G5 | 列表中展示「约第 N 页」提示（跳转时实时计算，可缓存于 UI 状态） |
| G6 | 内部用户详情页与外部分享页行为一致（只读/可编辑态均可定位） |
| G7 | 不影响现有保存版本、分页、自定义导出水印等能力 |

### 2.2 非目标（Out of Scope）

| 项 | 说明 |
|----|------|
| 将 `page_index` 写入 `contract_change` | 网页分页是运行时结果，存库会过期 |
| 像素级 / PDF 截图 Diff | 不做 |
| 实时协同 OT 操作回放 | 仍以「保存版本」为边界 |
| 一次高亮整版所有历史变更 | 本期默认 **单选一条变更** 高亮；可预留多选扩展 |
| 强制改库才能跳转 | P0 **零 schema 变更** 即可上线 |

## 3. 产品交互设计

### 3.1 主流程

```text
右侧「版本记录」点某一条变更
  → 若当前文档含该 block_id：
        翻到所在页 → 滚动到块 → 块描边 + 行内红绿 Diff 覆盖层
  → 若为「删除」且当前文档已无该块：
        提示「该段落已在后续版本删除」；可选：自动切到 from_version 只读视图再定位
  → 若当前正查看更旧/更新的历史版本且块不存在：
        优先切到 to_version（新增/修改）或 from_version（删除）只读视图再定位
```

### 3.2 「基于现在的版本」语义约定

用户口述「基于现在的版本」容易歧义，产品上明确为：

| 场景 | 行为 |
|------|------|
| **默认（推荐）** | Diff 展示该变更产生时的 **from→to** 文本对比；**定位落点**优先落在 **当前编辑器正在展示的文档**（最新或正在查看的历史版本）中同 `block_id` 的块 |
| 当前文档无此块 | 自动切换到能看到该块的版本快照（见上），并 Toast 说明 |
| 不采用 | 「把当前最新稿整篇与任意旧版再算一遍全量 Diff」——成本高且与单条变更记录不对齐 |

一句话：**列表里点的是哪次改动，纸面上就高亮那次改动；跳转尽量留在用户当前上下文，找不到块再切版本。**

### 3.3 UI 草案

**时间线条目增强**

- 整条可点，或右侧增加「定位」图标按钮（避免误触折叠区）
- 副文案：`约第 N 页`（能算出才显示）
- 选中态：条目左边框高亮，与纸面高亮联动
- 类型色沿用现有：新增绿 / 删除红 / 修改蓝

**纸面高亮**

| 变更类型 | 表现 |
|----------|------|
| 新增 `change_type=0` | 整块浅绿底；可选整段视为「绿增」 |
| 删除 `change_type=1` | 若块仍在（未切版本）：红底+删除线；若已不在：幽灵块或仅提示 |
| 修改 `change_type=2` 文本 | 块内行内：`<del>` 红底删除线 + `<ins>` 绿底 |
| 修改-样式 | 块描边 + Tooltip「样式变更：…」；**不做假文本 Diff** |
| 修改-表格 | 整表描边；单元格级红绿可作为 P2 |

**退出高亮**

- 再次点击同一条目 / 点「清除高亮」/ 开始编辑输入时自动清除（避免 contentEditable 与覆盖层冲突）

### 3.4 与「历史版本-查看」关系

| 入口 | 作用 |
|------|------|
| 历史版本「查看」 | 整版切换只读快照（已有） |
| 变更「定位」 | 单块跳转 + Diff 高亮（本期） |

二者互补：先定位单点，必要时再「查看」整版。

## 4. 技术方案

### 4.1 总体架构

```text
ChangeTimeline.onLocate(change)
        │
        ▼
ContractDetailPage / SharePage
  · resolveTargetDocument(change)   // 当前 doc 或切 from/to 版本
  · editorRef.jumpToBlock(blockId)
  · editorRef.setChangeHighlight(highlightState)
        │
        ▼
DocumentEditor
  · findPageIndex(pageIds, blockId) → setCurrentPage
  · DOM [data-block-id] scrollIntoView
  · ChangeDiffOverlay（只读层，pointer-events 可按需）
        │
        ▼
utils/textDiff.ts  // 前端 LCS / 词级 Diff → {type,text}[]
```

### 4.2 为何不落库页码

网页分页依赖测量（字号、边距、视口）；同一 `block_id` 在不同时刻可能落在不同页。

**跳转时计算：**

```ts
const pageIndex = findPageIndex(pageIds, change.block_id) // 0-based
// UI 展示：第 pageIndex + 1 页
```

列表「约第 N 页」：对当前 `documentContent`（或 viewingVersion）用编辑器暴露的 `getPageIndexForBlock(blockId)` 批量查询；编辑器未就绪时可不显示。

### 4.3 编辑器 API 扩展

```ts
export interface DocumentEditorHandle {
  // …现有
  /** 跳转到包含该 block 的页并滚动到块；找不到返回 false */
  jumpToBlock: (blockId: string) => Promise<boolean>
  /** 设置/清除当前变更高亮（Git 风格） */
  setChangeHighlight: (state: ChangeHighlightState | null) => void
  /** 查询 block 当前所在页（0-based，找不到 -1） */
  getPageIndexForBlock: (blockId: string) => number
}

export interface ChangeHighlightState {
  blockId: string
  changeType: 0 | 1 | 2
  oldText: string
  newText: string
  /** style | text | table | structure，前端可从 change_reason 粗分 */
  kind?: 'text' | 'style' | 'table' | 'structure'
}
```

实现要点：

1. `jumpToBlock`：`findPageIndex` → `setCurrentPage` → `requestAnimationFrame`/`setTimeout` 等待分页 remount → `querySelector([data-block-id="..."])` → `scrollIntoView({ block: 'center' })`。
2. 高亮层：优先 **覆盖在块上方的只读层**（不改 `contentEditable` 内部 HTML），避免破坏光标与保存序列化。
3. 编辑中若用户聚焦该块，自动 `setChangeHighlight(null)`。

### 4.4 行内 Diff 算法（前端）

新建 `frontend/src/utils/textDiff.ts`：

| 策略 | 说明 |
|------|------|
| P0 | 按「字」或按「词」（中文按字、英文按空格）做 LCS，输出 `equal | insert | delete` 片段 |
| 展示 | `delete` → 红底删除线；`insert` → 绿底；`equal` → 常态 |
| 截断 | DB 中 `old/new_content` 可能已被后端截断（约 500 字）；过长时提示「摘要 Diff」，完整对比可点「加载完整块」（P1：拉 from/to 版本 JSON 取全文） |

样式类建议：

```css
.doc-change-del { background: rgba(255, 82, 82, 0.18); text-decoration: line-through; color: #a8071a; }
.doc-change-add { background: rgba(82, 196, 26, 0.18); color: #237804; }
.doc-block--change-focus { outline: 2px solid #1677ff; outline-offset: 2px; }
```

### 4.5 各类变更处理矩阵

| change_type / 特征 | 跳转目标文档 | 纸面表现 |
|--------------------|--------------|----------|
| 0 新增 | 优先当前；否则 `to_version` | 绿底整块 |
| 1 删除 | 优先当前若仍存在；否则 `from_version` | 红底整块或幽灵提示 |
| 2 文本修改 | 当前或 `to_version` | 行内红绿 |
| 2 且 reason 含「样式」 | 同上 | 描边 + 文案，不行内假 Diff |
| 2 表格 | 同上 | 表级描边；P2 单元格 |

### 4.6 时间线组件改动

`ChangeTimeline` 新增：

```ts
interface ChangeTimelineProps {
  changes?: ContractChange[]
  versions?: ContractVersionItem[]
  loading?: boolean
  /** 当前激活的变更 id */
  activeChangeId?: number | null
  /** 点击定位 */
  onLocateChange?: (change: ContractChange) => void
  /** 可选：blockId → 页码映射，用于展示「约第 N 页」 */
  pageIndexByBlockId?: Record<string, number>
}
```

条目增加：

- `button`「定位」或整行 `role="button"`
- 显示页码：`pageIndexByBlockId[block_id] >= 0 ? \`约第 ${n+1} 页\` : ''`

### 4.7 详情页编排逻辑（伪代码）

```ts
async function handleLocateChange(change: ContractChange) {
  const doc = viewingVersion?.document_content ?? documentContent
  const hasBlock = doc?.blocks?.some(b => b.id === change.block_id)

  if (!hasBlock) {
    const versionId = change.change_type === 1
      ? change.from_version_id
      : change.to_version_id
    await loadVersionIntoViewer(versionId) // 复用现有查看历史版本
    message.info('已切换到包含该变更的版本以便定位')
  }

  const ok = await editorRef.current?.jumpToBlock(change.block_id)
  if (!ok) {
    message.warning('无法定位到该段落（可能已被后续大幅改写）')
    return
  }

  editorRef.current?.setChangeHighlight({
    blockId: change.block_id,
    changeType: change.change_type as 0|1|2,
    oldText: change.old_content ?? '',
    newText: change.new_content ?? '',
    kind: inferKind(change),
  })
  setActiveChangeId(change.id)
}
```

### 4.8 后端 / 数据模型

#### P0（推荐先做）：不改库

现有字段足够跳转与摘要 Diff。

#### P1（可选增强）

| 改动 | 收益 |
|------|------|
| `contract_change.change_subtype` VARCHAR(32) | 区分 `text` / `style_block` / `style_run` / `table` / `structure`，免解析 `change_reason`（V3.2 已提过未落库） |
| `GET /changes?to_version_id=` | 避免 `page_size=50` 截断导致某版本变更不全 |
| 跳转时按需 `GET /versions/:id` | 已有接口，取完整块文本做精确 Diff |

#### 明确不做

- 不增加 `page_index` 列  
- 不强制落库 `text_diff_ops`（除非后续要做服务端稳定偏移）

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| 分页 remount 后 DOM 未就绪 | `jumpToBlock` 内短延迟重试 2–3 次 |
| contentEditable 与覆盖层冲突 | 覆盖层默认 `pointer-events: none`；编辑时清除高亮 |
| `old/new_content` 截断 | UI 标注「摘要」；P2 拉版本全文 |
| 块 id 在后续编辑中被拆分/合并 | 找不到则提示；不硬编码页码 |
| 列表仅 50 条 | P1 按版本过滤拉取；或增大 page_size |
| 外部分享只读 | 同样支持定位；不可切「编辑清除」时用「清除高亮」按钮 |

## 9. 验收标准

| 标准 | 说明 |
|------|------|
| 可定位 | 任意有 `block_id` 的文本变更，1 次点击内到达对应页可见区域 |

## 10. 开放问题（实施前可与产品确认）

1. **删除类变更**：仅 Toast，还是自动切换到 `from_version` 只读？  
2. **高亮持续时间**：常驻到手动清除，还是 5s 后自动淡出？  
3. **是否允许同时高亮多条**（同页多块）？本期默认单选。  
4. **导出 PDF 是否带红绿 Diff**？建议 **否**（审计导出保持净稿；Diff 仅编辑态辅助）。

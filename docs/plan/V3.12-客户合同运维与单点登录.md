## 1. 背景与目标

### 1.1 问题

| # | 现象 | 影响 |
|---|------|------|
| P1 | 客户详情只能「从模板添加合同」，不能删除本合同下的合同 | 误建合同只能去合同管理页删，或删整客户 |
| P2 | 合同名称创建后不可改 | 客户侧命名纠错、复用模板后改名均不便 |
| P3 | 模板池已有 `PUT /templates/:id` 元数据接口，前端未接线 | 只能上传时定名，后续改名需重传 |
| P4 | 侧栏「数据统计」为占位页；「合同管理」与客户/模板路径重叠 | 导航噪音；合同入口应收敛到客户与首页 |
| P5 | JWT 存 localStorage，多端可同时持有效 Token；`last_login_*` 仅写库不展示，无设备/会话表 | 无法单点在线、无法审计登录、无法提示「已在别处登录」 |

### 1.2 需求

| # | 需求 | 说明 |
|---|------|------|
| R1 | 客户详情删合同 | 在客户详情的合同列表支持删除（二次确认）；复用现有 `DELETE /api/contracts/:id` |
| R2 | 客户详情重命名合同 | 支持修改 `contract_name`；落库后列表/详情/首页同步 |
| R3 | 模板池重命名 | 列表与/或详情支持改 `template_name`（可顺带改 description）；调用已有 `PUT /api/templates/:id` |
| R4 | 菜单调整 | **移除**「数据统计」菜单与路由入口；**隐藏**「合同管理」菜单（路由可保留深链兼容，不在侧栏暴露） |
| R5 | 单点登录 + 留痕 | 同一账号仅允许一个有效会话；新登录踢掉旧会话；旧端弹窗仅「退出登录」；记录每次登录时间、设备、IP，并维护「最后一次登录」展示字段 |

### 1.3 非目标

| 项 | 说明 |
|----|------|
| 真实数据统计看板 | 本次直接下线入口，不做统计实现 |
| 删除合同管理页代码 | 仅隐藏菜单；`/contracts` 深链与首页「最近合同」跳转详情可保留 |
| 短信/邮箱二次验证、设备白名单 | 不做 |
| Redis 分布式会话 | 默认同机 MySQL 会话表；多实例部署时再迁 Redis（见风险） |
| 分享协作者单点 | 外部分享无 JWT 体系，不在本次范围 |
| 合同批量重命名 / 模板批量重命名 | 不做 |

## 2. 已确认产品规则

| # | 议题 | 结论 |
|---|------|------|
| D1 | 客户详情删合同 | **软删语义与合同列表一致**（走现有 Delete 接口）；二次确认；删除后刷新客户下合同列表 |
| D2 | 合同重命名入口 | **客户详情为主入口**；合同详情页标题旁可选「重命名」（同一 API，体验一致） |
| D3 | 模板重命名入口 | **模板池列表**操作列 + 详情页标题旁均可；同一 `UpdateMeta` |
| D4 | 「合同管理」 | **侧栏隐藏**；不删路由，避免已收藏链接 404；首页最近合同仍跳 `/contracts/:id` |
| D5 | 「数据统计」 | **移除菜单 + 移除路由**（或重定向首页）；占位页删除 |
| D6 | 重复登录策略 | **后来者优先**：新设备登录成功 → 旧会话立即失效；旧端下次请求或心跳检测到后弹窗 |
| D7 | 被挤下线 UX | **不可继续操作**：`Modal` 不可关闭、无「忽略」；唯一按钮「退出登录」→ `clearAuth` + 跳转 `/login` |
| D8 | 登录留痕字段 | 每次登录记：`login_time`、`login_ip`、`user_agent`（解析为设备摘要）、`session_id`；用户表同步 `last_login_time` / `last_login_ip` /（新增）`last_login_device` |
| D9 | 留痕可见性 | 本期：**本人**可在个人入口或登录后短暂提示「上次登录」；管理员用户列表可展示最后登录时间/IP/设备（可选 Phase B） |

## 3. 用户流程

### 3.1 客户详情：删合同 / 重命名

```text
客户详情 → 合同列表行操作
  →「重命名」→ Modal 输入新名称 → PUT /api/contracts/:id → 刷新列表
  →「删除」→ Popconfirm → DELETE /api/contracts/:id → 刷新列表
  →「打开」→ 仍跳 /contracts/:id（详情编辑）
```

### 3.2 模板池重命名

```text
模板池列表 / 模板详情
  →「重命名」→ Modal（名称必填，说明可选）
  → PUT /api/templates/:id { template_name, description? }
  → 刷新列表或本地更新标题
```

### 3.3 单点登录

```text
【设备 B】输入账号密码登录成功
  → 创建 session_token（写入 JWT 或独立 jti）
  → 写入 user_login_log；更新 sys_user.last_login_*
  → 将该用户其余 session 标记 revoked

【设备 A】仍打开系统
  → 任意 API 返回 401 + code=40105（账号已在其他设备登录；40102 留给验证码）
     或 WS/轮询 /api/auth/session 返回 kicked
  → 全局弹窗：文案「您的账号已在其他设备登录（IP / 设备 / 时间）」
  → 仅「退出登录」→ 清 Token → /login
```

## 5. 方案设计

### 5.1 客户详情删合同（R1）

**前端**（`CustomerDetailPage.tsx`）

- PC Table / 移动卡片增加操作：打开、重命名、删除
- 删除：`Popconfirm` → `deleteContract(id)` → `message.success` → 重新 `getCustomerContracts`
- 权限：仅合同所有者（与现 API 一致）；锁定合同是否允许删——**与合同列表保持一致**（若列表允许删已确认合同则详情同样允许；否则统一禁止并提示）

**后端**：无新接口。

### 5.2 合同重命名（R2）

**后端**

- `PUT /api/contracts/:id`  
  Body：`{ "contract_name": "..." }`  
  校验：非空、长度上限（建议 ≤ 128，与创建一致）、归属当前用户  
  锁定合同：**允许改名**（仅元数据，不改文档）；或与产品确认「已确认不可改名」——默认 **允许**，便于归档命名
- Repository：`UpdateContractName(ctx, id, userID, name)`
- Audit（可选）：写 `contract_audit_log` `RENAME_CONTRACT`

**前端**

- `contractApi.updateContractMeta(id, { contract_name })`
- 客户详情 Modal；合同详情页标题旁编辑图标（复用同一 Modal 组件更佳）

### 5.3 模板池重命名（R3）

**后端**：已有，无需改契约（可复查长度校验）。

**前端**

- `TemplateListPage` / `TemplateDetailPage` 调用 `updateTemplateMeta`
- Modal：模板名称必填、说明可选

### 5.4 菜单（R4）

**前端** `MainLayout.tsx` + `App.tsx`

- 从 `buildMenuItems` 删除 `/statistics`、`/contracts`
- 删除或重定向 `/statistics` 路由到 `/`

- 首页文案若写「去合同管理页」→ 改为「去客户管理」或「查看合同详情」

### 5.5 单点登录与留痕（R5）

#### 5.5.1 数据模型（建议 `migrate_v10.sql`）

```sql
-- 用户会话（单点：每用户仅一条 active，或多条但仅最新 valid）
CREATE TABLE user_session (
  id              BIGINT       NOT NULL,
  user_id         BIGINT       NOT NULL,
  session_token   VARCHAR(64)  NOT NULL COMMENT 'jti / 会话随机串，写入 JWT',
  login_ip        VARCHAR(64)  DEFAULT NULL,
  user_agent      VARCHAR(512) DEFAULT NULL,
  device_label    VARCHAR(128) DEFAULT NULL COMMENT '解析摘要，如 Chrome / iOS',
  status          TINYINT      NOT NULL DEFAULT 1 COMMENT '1有效 0已踢/退出',
  login_time      DATETIME     NOT NULL,
  last_seen_time  DATETIME     DEFAULT NULL,
  revoke_time     DATETIME     DEFAULT NULL,
  revoke_reason   VARCHAR(32)  DEFAULT NULL COMMENT 'replaced|logout|ban',
  PRIMARY KEY (id),
  UNIQUE KEY uk_session_token (session_token),
  KEY idx_user_status (user_id, status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户登录会话';

-- 登录留痕（只增不改，供审计）
CREATE TABLE user_login_log (
  id              BIGINT       NOT NULL,
  user_id         BIGINT       NOT NULL,
  session_id      BIGINT       DEFAULT NULL,
  login_ip        VARCHAR(64)  DEFAULT NULL,
  user_agent      VARCHAR(512) DEFAULT NULL,
  device_label    VARCHAR(128) DEFAULT NULL,
  login_time      DATETIME     NOT NULL,
  result          TINYINT      NOT NULL DEFAULT 1 COMMENT '1成功 0失败',
  fail_reason     VARCHAR(64)  DEFAULT NULL,
  PRIMARY KEY (id),
  KEY idx_user_time (user_id, login_time)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户登录日志';

ALTER TABLE sys_user
  ADD COLUMN last_login_device VARCHAR(128) NULL COMMENT '最后登录设备摘要' AFTER last_login_ip;
```

#### 5.5.2 JWT 改造

- Claims 增加 `sid`（session_token）
- 登录成功：
  1. 生成 `sid`
  2. 将该用户其他 `user_session.status=1` 置 `0`，`revoke_reason=replaced`
  3. 插入新 session + login_log
  4. 更新 `sys_user.last_login_time/ip/device`
  5. 签发含 `sid` 的 JWT
- `JWTAuth` / `JWTAuthFlexible`：解析后查 `user_session`：`token` 匹配且 `status=1`，否则 401  
  - 业务码建议：`40101` 未登录/过期；`40105` **被其他设备挤下线**（前端据此弹专用窗；`40102` 为验证码相关）
- `POST /api/auth/logout`：当前 session `status=0`，`revoke_reason=logout`
- 可选：`GET /api/auth/session` 返回 `{ active, kicked_reason, last_login }` 供前端轻量探测

#### 5.5.3 前端

- `request.ts` 响应拦截：若 `code===40105`，打开全局 `KickedModal`（挂在 `MessageBridge` / `App` 层），禁止再弹普通 toast 刷屏
- Modal：展示「账号已在其他设备登录」+ 可选上次/本次 IP、设备、时间（若接口带回）
- 按钮仅「退出登录」→ `clearAuth` + `navigate('/login')`；`maskClosable=false`，`keyboard=false`
- 登录成功后可选 Toast：「上次登录：时间 · 设备 · IP」（来自 login 响应 `previous_login`）
- WebSocket：内部协作连接鉴权失败时同样触发踢下线逻辑

#### 5.5.4 设备摘要解析

- 服务端用 `User-Agent` 粗解析：`Chrome / Windows`、`Safari / iPhone` 等；解析失败则截断 UA 前 64 字
- 不引入重型 UA 库（可后续替换）

## 9. 风险与对策

| 风险 | 对策 |
|------|------|
| HTTP 多开标签同浏览器共享 localStorage | 同浏览器多标签视为同一会话（符合预期）；挤下线针对**不同浏览器/设备** |
| 后端多副本无共享内存 | **会话以 MySQL 为准**，勿用进程内 map |
| 中间件每请求查库 | `user_session` 按 `session_token` 唯一索引；可加短 TTL 本地缓存（可选） |
| 旧客户端无 sid 的 JWT | 上线后强制重新登录；或兼容期：无 sid 的 Token 一律视为失效 |
| 电子章图片 `?token=` 走 Flexible 鉴权 | 同样校验 sid，避免被踢后仍能加载私有图 |
| 删除合同不可恢复 | 文案明确；与列表删除一致；后续可做回收站（非本期） |
